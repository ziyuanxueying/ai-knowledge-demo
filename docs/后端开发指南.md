本文档面向后端开发者，说明 `server/` 目录的架构、各模块职责、API 设计、数据存储与扩展方式。

## 一、技术栈

| 技术 | 版本 | 用途 |
|------|------|------|
| Node.js | 18+ | 运行时 |

## 三、核心架构

### 1. 请求处理链路

启动：`bootstrap()` → `initDB()`（扩展 / 建表 / HNSW / JSON 种子迁移）→ `seedIfEmpty()` → 监听端口。退出时 `SIGTERM`/`SIGINT` 关闭连接池。

```
客户端请求
   ↓
app.js（cors / json / 信任一跳代理 / 访问日志）
   ↓
限流（AI 接口默认 20 次/分钟，可用 AI_RATE_LIMIT；普通接口 120 次/分钟）
   ↓
路由分发
   ├─ GET  /api/health     → ping Postgres（失败 503）
   ├─ POST /api/chat       → chat.js（AI 限流）
   ├─ POST /api/agent      → agent.js（AI 限流）
   ├─ POST /api/compare    → compare.js（AI 限流）
   ├─ /api/knowledge       → knowledge.js
   ├─ /api/prompts         → prompts.js
   └─ /api/history         → history.js
   ↓
业务层（services / agent / data）
   ↓
通义千问（Chat / Embeddings）  +  PostgreSQL+pgvector  +  prompts.json
```

生产构建后 Express 托管 `client/dist`，非 `/api` 的 GET 回退 `index.html`。

### 2. 工作模式的后端实现

#### 对话模式（[chat.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/server/src/routes/chat.js)）

1. 接收 `{ message, sessionId, scenario, temperature?, maxTokens? }`（采样参数非法则回退 `.env` 默认）
2. 从 store 读会话；**长对话摘要**：未摘要的早期历史 ≥ 2 条时，调 `summarizeHistory` 写回 `sessions.summary`
3. 组装 messages：system（scenario → promptStore，含变量插值）+ 摘要 system（如有）+ 最近 6 条原文 + 当前问题
4. 调用模型前推送 SSE `messages`（含 chars / 估算 tokens / summary），供消息预览面板
5. `streamChat` 流式推 token，结束后 `appendMessage` 写入 Postgres

#### Agent 模式（[agent.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/server/src/routes/agent.js) + [agent.service.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/server/src/agent/agent.service.js)）

1. 接收 `{ task, sessionId }`，复用同一套会话表
2. **RAG 预检索**（非问候）：`searchEntriesSemantic(task, 3, 0.3)`，命中则注入 system，并先推 `thinking` + `tool`（step 1）
3. Agent 循环最多 `MAX_ITERATIONS = 8`：`tool_choice: 'auto'`；有 `tool_calls` 则 `executeTool` 后以 `role: 'tool'` 回灌；`stop` 则按字符分片推 `content`
4. 助手消息带 `toolSteps` JSON 存库。SSE：`session` / `thinking` / `tool` / `content` / `usage` / `done` / `aborted`

> qwen-turbo 对概念题常不调检索工具，预检索保证 RAG 生效。详见 [AI学习指南](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/docs/AI学习指南.md) 第四章第 6 节。

#### 知识库（[knowledge.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/server/src/routes/knowledge.js)）

RESTful CRUD + `/search`（keyword / semantic / compare）+ `/stats` + `/embeddings/:action`。具名路由必须注册在 `/:id` 之前。

#### A/B 对比（[compare.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/server/src/routes/compare.js) + [judge.service.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/server/src/services/judge.service.js)）

同一问题两套 `{ temperature, maxTokens, scenario, label }` **并行**流式输出，事件带 `variant: 0|1`。不写会话、不摘要、不 RAG。`judge: true` 时两路结束后用低温模型按准确性 / 完整性 / 清晰度 / 实用性打分（强制 JSON）。

## 五、数据存储

会话 / 消息 / 知识库 / 向量在 PostgreSQL（需启用 pgvector 扩展）。`prompts.json` 落到 `config.dataDir`（`DATA_DIR`，默认 `server/src/data`）。

本地开发可先起数据库：

```bash
docker compose up -d   # 项目根目录，镜像 pgvector/pgvector:pg16
```

默认连接串：`postgresql://postgres:postgres@localhost:5432/ai_knowledge`。

### 1. PostgreSQL + pgvector（[db.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/server/src/data/db.js)）

启动时 `initDB()` 会 `CREATE EXTENSION IF NOT EXISTS vector`、建表、建索引：

- `messages("sessionId", seq)`：按会话取消息
- `kb_entries` HNSW（`embedding vector_cosine_ops`）：语义检索；失败则顺序扫描并打日志
- `kb_entries("updatedAt" DESC)`：列表排序

`embedding` 写入用字符串 `'[1,2,...]'` + `$n::vector`。维度由 `EMBEDDING_DIM`（默认 1024）在建表时固定；换维度需重建表并 `regenerate` 向量。

托管库 SSL：`PGSSL=true` 或 `PGSSLMODE=require` / `no-verify`。连接池大小 `PGPOOL_MAX`（默认 10）。

| 表 | 字段 | 说明 |
|------|------|------|
| `sessions` | id, title, summary, summaryUpTo, createdAt, updatedAt | 会话（含长对话摘要） |
| `messages` | id, seq, sessionId, role, content, usage, toolSteps, createdAt | 消息（外键关联 session，`seq` 保证插入顺序） |
| `kb_entries` | id, title, keywords, category, content, embedding, createdAt, updatedAt | 知识库；`embedding` 为 `vector(1024)`（维度由 `EMBEDDING_DIM` 决定） |

**自动迁移**：[db.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/server/src/data/db.js) 的 `initDB()` 在表为空且旧的 `history.json` / `knowledge.json` 存在时，自动导入 Postgres（幂等，已有数据时不执行）。

### 2. 会话历史（[store.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/server/src/data/store.js)）

异步 API（`pg`），路由层需 `await`。常用导出：

- `listSessionSummaries()` → `{ sessions: [{ id, title, createdAt, updatedAt, messageCount }] }`
- `readAllSessions()` → `{ sessions: [{ ...session, messages: [...] }] }`
- `createSession(title)` / `getSession(id)` / `appendMessage(id, msg)` / `deleteSession(id)`
- `updateSessionTitle(id, title)` / `updateSessionSummary(id, summary, summaryUpTo)`

`appendMessage` 在事务里 `SELECT … FOR UPDATE` 再插消息、改标题，避免并发丢更新。列表接口走 `listSessionSummaries()`（`COUNT` 聚合），不把全部消息拉回 Node。

会话结构：

```json
{
  "id": "s_xxx",
  "title": "useEffect 用法",
  "summary": "",                // 早期对话摘要（长对话压缩用）
  "summaryUpTo": 0,             // 摘要覆盖到第几条 user/assistant 消息
  "createdAt": "...",
  "updatedAt": "...",
  "messages": [
    { "role": "user", "content": "..." },
    { "role": "assistant", "content": "..." }
  ]
}
```

### 3. 知识库（[kbStore.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/server/src/data/kbStore.js)）

每条条目独立一行，`embedding` 用 pgvector 的 `vector` 类型。语义检索在数据库内用 `<=>` 算余弦距离，`score = 1 - distance`，并走 HNSW 索引（`vector_cosine_ops`）。

**两种检索**：
- `searchEntries(query)`：关键词匹配（title + keywords + content + category，SQL `strpos` / JSON 关键词）
- `searchEntriesSemantic(query, topK=3, threshold=0.3)`：语义检索，先 `ensureEmbeddings()` 懒补齐，再按余弦距离取 Top-K

**向量化**：
- `createEntry` / `updateEntry`：保存时自动生成/重新生成向量
- `ensureEmbeddings()`：补齐缺失向量（首次语义检索时触发）
- `regenerateAllEmbeddings()`：全量重新生成（换模型时用）
- `stats()`：`{ total, embedded, pending }`

**降级**：未配置 `DASHSCOPE_API_KEY` 时向量化失败，`embedding` 置空，语义检索自动退化为关键词检索。

### 4. Prompt 场景（[promptStore.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/server/src/data/promptStore.js)）

存到 `$DATA_DIR/prompts.json`。结构为 `{ scenarios: { id: { name, content, updatedAt } } }`。

- 首次访问 `/api/prompts` 时，若文件不存在，自动写入种子（`frontend_dev` + `default` 两个场景），让前端 Prompt 编辑器开箱即有内容
- `applyVars(content, extraVars)` 做 `{{datetime}}` 等变量插值，渲染时才替换
- `getRenderedPrompt(scenario)` 返回插值后的 prompt，发给模型用
- `getRawPrompt(scenario)` 返回原始 prompt（含 `{{}}`），编辑器显示用
- `getSystemPrompt(scenario)`（在 [knowledge.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/server/src/data/knowledge.js)）优先读 `prompts.json`，读不到回退 [system.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/server/src/prompts/system.js) 硬编码

## 六、Agent 工具扩展

### 添加新工具的三个步骤

以"查 GitHub star 数"为例：

#### 步骤 1：写工具函数

在 [tools.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/server/src/agent/tools.js) 中：

```javascript
async function getGithubStars(repoName) {
  try {
    const res = await fetch(`https://api.github.com/repos/${repoName}`);
    const data = await res.json();
    return `仓库 ${repoName} 有 ${data.stargazers_count} 个 star`;
  } catch (e) {
    return `查询失败：${e.message}`;
  }
}
```

#### 步骤 2：注册到 TOOLS 对象

```javascript
export const TOOLS = {
  search_frontend_kb: searchFrontendKb,
  get_npm_package_info: getNpmPackageInfo,
  analyze_code: analyzeCode,
  get_github_stars: getGithubStars,  // 新增
};
```

#### 步骤 3：添加 JSON Schema 定义

在 `tools` 数组中：

```javascript
{
  type: 'function',
  function: {
    name: 'get_github_stars',
    description: '查询 GitHub 仓库的 star 数量',
    parameters: {
      type: 'object',
      properties: {
        repoName: { type: 'string', description: '仓库名，如 facebook/react' }
      },
      required: ['repoName']
    }
  }
}
```

重启后端，Agent 即可自主决定是否调用新工具。

### 工具函数的注意事项

- **必须异步**（`async`），因为可能涉及网络请求
- **必须返回字符串**，模型据此理解执行结果
- **必须 try/catch**，失败时返回错误信息给模型（而不是抛异常中断 Agent）
- **参数从模型的 `tool_calls` 解析**，注意类型转换

## 六点五、RAG：Embedding 服务与预检索

### Embedding 服务（[embedding.service.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/server/src/services/embedding.service.js)）

复用通义千问 OpenAI 兼容端点，只是调 `/embeddings` 而非 `/chat/completions`：

```javascript
const res = await client.embeddings.create({
  model: config.dashscope.embeddingModel,  // text-embedding-v3
  input: ['文本1', '文本2'],  // 批量，返回多个向量
});
// res.data 按 index 排序，每项 .embedding 是 1024 维数组
```

导出：
- `embedTexts(texts)`：批量向量化
- `embedQuery(text)`：单条查询向量化
- `cosineSimilarity(a, b)`：公式对照用；线上检索走 pgvector，不经过此函数
- `hasEmbeddingConfig()`：是否配了 API Key

### Agent 预检索注入（[agent.service.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/server/src/agent/agent.service.js)）

`runAgent` 在进入模型循环前，对非问候类查询先做语义检索：

```javascript
if (shouldForceKbRetrieve(task)) {
  const results = await searchEntriesSemantic(task, 3, 0.3);
  if (results.length > 0) {
    ragContext = formatSearchResultText(task, results);
    yield { type: 'thinking', step: 1, plan: [...] };  // 推送给前端展示
    yield { type: 'tool', step: 1, ... };
  }
}
// 注入 system prompt
const systemContent = ragContext
  ? `${AGENT_SYSTEM_PROMPT}\n\n## 已检索到的知识库内容...\n${ragContext}`
  : AGENT_SYSTEM_PROMPT;
```

> `shouldForceKbRetrieve(task)` 用简单正则排除纯问候（你好/谢谢等），其余都预检索。模型循环步骤编号用 `stepBase` 偏移，避免与预检索的 step 1 冲突。

## 七、SSE 流式实现

### 对话流式（[ai.service.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/server/src/services/ai.service.js)）

用 openai SDK 的 `stream: true`：

```javascript
const stream = await openai.chat.completions.create({
  model, messages, stream: true, temperature,
});
for await (const chunk of stream) {
  const content = chunk.choices[0]?.delta?.content;
  if (content) {
    res.write(`data: ${JSON.stringify({ content })}\n\n`);
  }
}
res.write('data: [DONE]\n\n');
res.end();
```

### Agent 流式（[agent.service.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/server/src/agent/agent.service.js)）

Agent 的流式分两类：

1. **工具调用阶段**：非流式，一次返回完整 `tool_calls`，后端执行后推送 `thinking` / `tool` 事件
2. **最终答案阶段**：流式，按字符分片推送 `content` 事件

### SSE 响应头

```javascript
res.writeHead(200, {
  'Content-Type': 'text/event-stream',
  'Cache-Control': 'no-cache',
  'Connection': 'keep-alive',
});
```

### 中断处理

正确做法：监听 `res.on('close')` + `finished` 守卫，仅在客户端真实断开时才中断模型调用。

```javascript
let finished = false;
res.on('close', () => {
  if (!finished) {
    // 客户端断开，中止模型调用
    controller.abort();
  }
});
// 完成后
finished = true;
res.end();
```

> 注意：不要用 `req.on('close')`，它在请求体读完后立即触发，会误中断刚发出的模型调用。

```bash
QWEN_MODEL=qwen-max

```

### 3. 修改快捷问题

编辑 [knowledge.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/server/src/data/knowledge.js) 的 `QUICK_QUESTIONS` 数组。

见上文第六章「Agent 工具扩展」。

### 5. 重置知识库 / 会话历史

数据在 PostgreSQL。重置方式：

```bash
# 连上库后清空表，重启后端会按空表 + JSON 种子重新迁移
psql "$DATABASE_URL" -c 'TRUNCATE sessions, messages, kb_entries CASCADE;'
```

重启服务后，[db.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/server/src/data/db.js) 的 `initDB()` 检测到表为空且 `knowledge.json` / `history.json` 种子存在，会自动迁移。

## 十、常见问题

**Q: 启动报 `EADDRINUSE`？**
A: 3001 端口被占用。用 `lsof -i :3001` 找到进程 kill，或改 `config/index.js` 的 `port`。

**Q: API 调用报 401？**
A: `.env` 中 `DASHSCOPE_API_KEY` 错误或未配置。参考 [.env.example](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/server/.env.example)。

**Q: `--watch` 没自动重启？**
A: 确认 Node.js 版本 ≥ 18.11（`--watch` 是 18.11+ 特性）。用 `node -v` 检查。

**Q: Agent 一直转圈不返回？**
A: 可能模型陷入工具调用循环。本项目限制 `MAX_ITERATIONS = 8`（[agent.service.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/server/src/agent/agent.service.js)），可调小。也检查工具函数是否正常返回字符串。

**Q: SSE 连接立即断开？**
A: 检查中断监听是否用 `res.on('close')` 而非 `req.on('close')`（见上文第七章）。

**Q: 数据文件在哪？**
A:
- 会话 / 消息 / 知识库 / 向量：PostgreSQL（`DATABASE_URL`）
- `prompts.json`：`$DATA_DIR`（默认 `server/src/data/`）
- `knowledge.json` / `history.json`：源码里的 JSON 种子，表为空时导入 Postgres

**Q: 启动后看不到旧数据 / 数据被重置了？**
A: 检查 `DATABASE_URL` 是否指向同一套库；托管库重启应用不会丢数据。`prompts.json` 仍依赖 `DATA_DIR` / 持久卷。迁移逻辑只在表为空时触发，已有数据不会被种子覆盖。

**Q: 启动报「数据库初始化失败」？**
A: 确认 Postgres 已启动且启用了 pgvector。本地可用 `docker compose up -d`。托管库需允许 `CREATE EXTENSION vector`，或由管理员预先执行。需要 SSL 时设 `PGSSL=true` 或 `PGSSLMODE=no-verify`。

**Q: 向量化失败 / 状态条一直显示"待向量化"？**
A: 检查 `.env` 的 `DASHSCOPE_API_KEY` 是否正确配置。未配置时 `embedding` 置空，语义检索退化为关键词检索。配好后点界面的「补齐向量」或调 `POST /api/knowledge/embeddings/ensure`。

**Q: 换了 embedding 模型后检索不准？**
A: 旧向量是旧模型生成的，新旧维度/语义空间不一致。点界面的「重新生成全部向量」或调 `POST /api/knowledge/embeddings/regenerate` 全量重生成。

**Q: Agent 对概念问题不调检索工具 / 编造"据知识库"？**
A: 这是 qwen-turbo 工具调用不可靠。本项目已用预检索注入规避。若仍出现，确认 [agent.service.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/server/src/agent/agent.service.js) 的预检索代码未被注释，且 `shouldForceKbRetrieve` 未误判该查询为问候。

**Q: Node.js 的 `fetch` 报错？**
A: `fetch` 是 Node.js 18+ 内置。若版本较低，需升级 Node 或安装 `node-fetch`。
