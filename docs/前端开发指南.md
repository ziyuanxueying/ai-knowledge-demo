## 三、核心架构

### 1. 视图与模式切换

[App.jsx](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/client/src/App.jsx) 管理两个状态：

- `view`: `'chat'` | `'knowledge'` — 切换聊天视图与知识库管理视图
- `mode`: `'chat'` | `'agent'` — 聊天视图内的对话/Agent 模式

```
Sidebar（始终显示）
  ├─ 「+ 新建对话」→ handleNewChat（切回 chat 视图）
  ├─ 「📚 知识库」→ setView('knowledge')
  └─ 会话列表    → handleSwitchSession（切回 chat 视图）

Main（根据 view 切换）
  ├─ view === 'knowledge' → <KnowledgeBase />
  └─ view === 'chat'       → 聊天界面
       ├─ 顶部 header（对话/Agent 模式切换）
       ├─ <ChatWindow />（messages + mode）
       └─ <InputBox />
```

### 2. 两个 Hook 的分工

| Hook | 模式 | 接口 | 状态 |
|------|------|------|------|
| [useChat.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/client/src/hooks/useChat.js) | 对话 | `/api/chat` | messages, sessions, currentSessionId, loading, error |
| [useAgent.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/client/src/hooks/useAgent.js) | Agent | `/api/agent` | messages（含 steps）, currentSessionId, loading, error |

两者都封装了：发送、停止生成（AbortController）、新建会话、SSE 事件解析。
会话列表（sessions）**共用 useChat 的存储**，因为两种模式都存到后端同一份 history。

### 3. SSE 流式接收

[api.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/client/src/utils/api.js) 的 `streamChat` / `streamAgent` 用 fetch + ReadableStream 解析 SSE：

```javascript
// 对话模式：解析 data: {content} 分片
// Agent 模式：解析多种事件类型
const reader = res.body.getReader();
const decoder = new TextDecoder();
let buffer = '';
while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const lines = buffer.split('\n');
  buffer = lines.pop(); // 保留不完整的一行
  for (const line of lines) {
    if (line.startsWith('data: ')) {
      const data = JSON.parse(line.slice(6));
      // 根据 data.type 分发：content / thinking / tool / done ...
    }
  }
}
```

### 4. Agent 步骤渲染

[Message.jsx](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/client/src/components/Message.jsx) 在 Agent 模式下：

- 若 `message.steps` 有内容 → 渲染 [AgentSteps.jsx](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/client/src/components/AgentSteps.jsx)（步骤号、工具名、参数、结果）
- 若无步骤 → 显示「🤖 Agent 判断无需调用工具，直接回答」徽标

这样 Agent 模式下每条 AI 消息都有视觉区分，不会和对话模式混淆。

### 5. 知识库管理界面（含 RAG 检索对比）

[KnowledgeBase.jsx](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/client/src/components/KnowledgeBase.jsx) 实现完整 CRUD + RAG 可视化：

- **向量化状态条**：进度条 + "已向量化 X/Y 条" + 「补齐向量」/「重新生成全部向量」按钮
- **检索对比面板**：输入查询后并排展示「关键词检索」vs「语义检索」结果，语义列带相似度进度条。含示例词（函数记住外部变量 / 框架高效更新 DOM / 打包去无用代码）
- 列表：条目卡片（标题、分类、关键词标签、内容、更新时间）
- 搜索：title / keywords / content / category 任一命中
- 新增/编辑：弹窗表单（标题、分类、关键词逗号分隔、内容多行）
- 删除：确认后调用 API

保存/删除后自动刷新向量化状态（`refreshStats`）。

### 6. Prompt 实验室与消息预览面板

[PromptLab.jsx](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/client/src/components/PromptLab.jsx) 是 System Prompt 的在线编辑器：

- 左侧场景列表（`getPrompts()` 返回，与聊天页角色下拉框共用同一份数据）
- 右侧编辑名称 + textarea 内容，变量 chip（`{{datetime}}` 等）点击插入
- 「查看渲染后效果」展开变量插值后的最终文本
- 保存调 `PUT /api/prompts/:id`，后端写入 prompts.json，下一次对话立即生效

[MessagePreview.jsx](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/client/src/components/MessagePreview.jsx) 是消息预览面板：

- 数据来源：`/api/chat` 的 SSE `messages` 事件（在模型调用前推送），由 [useChat.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/client/src/hooks/useChat.js) 的 `onMessages` 回调存入 `previewMessages` state
- 默认折叠（蓝紫渐变横条只占 ~43px，不挤占消息区），展开显示每条消息的角色 badge / 字数 / 估算 token / 内容预览
- **关键实现细节**：展开/折叠用 `.is-open` 类 + CSS 控制，DOM 常驻——不要用 conditional render（`{expanded && ...}`），否则折叠时元素从 DOM 移除会造成高度塌陷的割裂感
- JSX 里展示字面花括号要转义：`{'{{}}'}`，直接写 `{{}}` 会被解析成空对象表达式导致渲染崩溃

聊天页顶部的「角色」下拉框在 [App.jsx](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/client/src/App.jsx) 中：启动时 `getPrompts()` 加载场景列表，切换时 `chat.setScenario(id)` + `chat.newChat()`（清空当前对话，避免新旧角色上下文混乱）。

## 四、API 调用封装

[api.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/client/src/utils/api.js) 封装所有后端接口：

| 函数 | 接口 | 用途 |
|------|------|------|
| `streamChat(params, callbacks)` | POST `/api/chat` | 对话流式 |
| `streamAgent(params, callbacks)` | POST `/api/agent` | Agent 流式 |
| `getQuickQuestions()` | GET `/api/chat/quick-questions` | 快捷问题 |
| `getSessions()` | GET `/api/history` | 会话列表 |
| `getSessionDetail(id)` | GET `/api/history/:id` | 会话详情 |
| `createSession(title)` | POST `/api/history` | 新建会话 |
| `deleteSession(id)` | DELETE `/api/history/:id` | 删除会话 |
| `getKnowledgeEntries()` | GET `/api/knowledge` | 知识库列表 |
| `createKnowledgeEntry(data)` | POST `/api/knowledge` | 新增条目（后端自动向量化） |
| `updateKnowledgeEntry(id, data)` | PUT `/api/knowledge/:id` | 更新条目（后端自动重新向量化） |
| `deleteKnowledgeEntry(id)` | DELETE `/api/knowledge/:id` | 删除条目 |
| `getKbStats()` | GET `/api/knowledge/stats` | 向量化状态 `{total, embedded, pending}` |
| `searchKnowledge(q, mode)` | GET `/api/knowledge/search?q=&mode=` | 检索：`keyword`/`semantic`/`compare` |
| `regenerateKbEmbeddings(action)` | POST `/api/knowledge/embeddings/:action` | 向量化：`ensure`/`regenerate` |
| `getPrompts()` | GET `/api/prompts` | Prompt 场景列表 + 可用变量 |
| `getPrompt(scenario)` | GET `/api/prompts/:id` | 单个 prompt（raw + 渲染后） |
| `updatePromptApi(scenario, data)` | PUT `/api/prompts/:id` | 保存 prompt，立即生效 |

SSE 事件类型（`/api/chat`）：`session`（会话 ID）、**`messages`（最终 messages 预览 + token 估算）**、`content`（流式文本块）、`usage`（token 用量）、`done`/`aborted`/`error`。

API 基础地址通过 Vite 代理（见 [vite.config.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/client/vite.config.js)），前端用 `/api/...` 相对路径，开发时自动转发到 `http://localhost:3001`。

## 五、开发流程

### 启动

```bash
cd client
npm install        # 首次
npm run dev         # 启动开发服务器（默认 5173，被占用自动切 5174）
npm run build       # 生产构建
npm run lint        # ESLint 检查
```

### Vite 代理配置

[vite.config.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/client/vite.config.js) 把 `/api` 代理到后端：

```javascript
server: {
  proxy: {
    '/api': {
      target: 'http://localhost:3001',
      changeOrigin: true,
    }
  }
}
```

前端代码用 `/api/...` 相对路径，无需关心后端端口。

## 七、无障碍（a11y）注意事项

项目用 Biome 检查无障碍规则，常见报错与解决：

| 规则 | 报错场景 | 解决方式 |
|------|----------|----------|
| `useKeyWithClickEvents` | `<div onClick>` 无键盘事件 | 改用 `<button>` |
| `useSemanticElements` | `<div role="button">` | 直接用 `<button>` |
| `noStaticElementInteractions` | `<div onClick>` 拦截点击 | 用 `<button>` 作 backdrop |
| `useSemanticElements` | `<div role="dialog">` | 用原生 `<dialog>` 或去掉 role |

原则：**可交互元素一律用 `<button>`**，避免 `<div onClick>`。按钮嵌套按钮是无效 HTML，需要拆成并列结构。

## 八、常见问题

**Q: 启动后端口 5173 被占用？**
A: Vite 会自动切到 5174/5175。若想固定端口，改 [vite.config.js](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/client/vite.config.js) 的 `server.port`。若有僵尸进程占用，用 `lsof -i :5173` 找到 PID 后 kill。

**Q: 修改文件后页面没更新？**
A: Vite HMR 通常即时生效。若没更新，检查终端是否有编译错误，或手动刷新浏览器。

**Q: AI 回复的代码没有高亮？**
A: 确认 [main.jsx](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/client/src/main.jsx) 引入了 highlight.js 主题 CSS，且 [Message.jsx](file:///Users/anyi/Desktop/AIDemos/ai-knowledge-demo/client/src/components/Message.jsx) 用了 `rehypeHighlight` 插件。

**Q: Agent 步骤面板不显示？**
A: 只有 AI 真的调用了工具才会显示步骤面板。问普通问题（不触发工具）时只会显示「直答」徽标。用欢迎页的 Agent 示例任务测试。

**Q: 知识库界面打不开？**
A: 确认后端已启动且 `/api/knowledge` 路由可访问。在浏览器直接访问 `http://localhost:3001/api/knowledge` 应返回 JSON。

**Q: 知识库顶部"向量化"状态条一直显示"待向量化"？**
A: 后端未配置 `DASHSCOPE_API_KEY`，向量化失败退化为关键词检索。配置好后点「补齐向量」按钮。

**Q: 检索对比面板的语义检索结果是空的？**
A: 三种可能：① 还没向量化（点「补齐向量」）；② 查询与所有条目相似度都低于 0.3（换更相关的查询，或后端调低阈值）；③ 后端 API Key 未配置。

**Q: Agent 模式下问概念问题，AI 回复上方没有「检索」步骤？**
A: 正常情况下 Agent 第一步应显示 `search_frontend_kb` 检索步骤（预检索注入）。若没有，可能是查询被 `shouldForceKbRetrieve` 判定为问候（如"你好"），或后端预检索代码被注释。
